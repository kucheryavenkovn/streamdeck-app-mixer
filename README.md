# App Mixer · Stream Deck + (Windows)

Локальный микшер аудиосессий Windows: восемь кнопок приложений и четыре валкодера.
Не использует Voicemeeter, не записывает звук, не требует администратора и не открывает сетевой сервер.

> С 2026-11-07 код живёт в отдельном репозитории. Плагин «Яндекс Музыка» вынесен
> в [`streamdeck-yamusic`](https://github.com/). Исходный монолитный репозиторий
> `D:\git\streamdeck` остался исследовательским (MiniFuse Desk).

## Состав

- `src/` — Node.js-логика плагина: `plugin.mjs` (вход), `controller.mjs`, `model.mjs`,
  `render.mjs`, `routing.mjs`, `bridge.mjs` (клиент JSON-протокола моста).
- `native/AudioBridge/` — автономный .NET-мост к Windows Audio Sessions API
  (self-contained single-file, .NET Runtime пользователю не нужен). Есть `--self-test`.
- `native/LaunchProbe/` — служебный инструмент проверки запуска приложений (не входит в пакет).
- `plugin/` — манифест, иконки (генерируются), layout валкодера, UI инспектора, лицензии.
- `scripts/` — сборка, генерация профиля, проверки.
- `tests/` — юнит-тесты (`node --test`).

## Сборка и установка

1. Бэкап: `pwsh -File scripts/backup.ps1`. Копируются данные `%APPDATA%\Elgato\StreamDeck`
   и ветка HKCU StreamDeck; файлы профилей проверяются SHA-256. Бэкап может содержать
   приватные настройки — не публиковать.
2. `npm ci`, `npm test`, `npm run build` (.NET SDK 10, Node.js 20+).
3. `npx streamdeck validate dist/local.tux.appmixer.sdPlugin`.
4. `npx streamdeck pack dist/local.tux.appmixer.sdPlugin -o dist`, открыть
   `dist/local.tux.appmixer.streamDeckPlugin` и подтвердить установку плагина.
   Режим разработчика не нужен.
5. Открыть `dist/AppMixer.streamDeckProfile` и импортировать **новый** профиль
   **App Mixer - Windows**. У пакета собственные UUID профиля, страниц и действий;
   старые профили не редактируются.

`npm run build` сохраняет уже созданный пакет нового профиля, чтобы повторная сборка
не порождала дубликаты. Удалять или заменять пользовательские профили сборка не умеет.

## Управление

| Действие | Результат |
|---|---|
| Коснуться секции табло | Выбрать валкодер для назначения; появляется цветная рамка |
| Нажать кнопку приложения | Назначить приложение выбранному валкодеру; если закреплённое приложение закрыто — запустить |
| Удерживать кнопку ≥650 мс | Закрепить/открепить кнопку впереди списка |
| Вращать валкодер | Изменить громкость (по умолчанию 10% за шаг) |
| Нажать и отпустить валкодер без вращения | Mute/unmute |
| Зажать и вращать валкодер | Предыдущая/следующая страница приложений |
| Удержать секцию табло | LOCK/unlock назначения валкодера |

Действия: «Приложение (слот)» (кнопка), «Канал микшера» (валкодер),
«Системный аудиовыход» и «Аудиовыход приложения» (валкодеры, перенос вывода).
Явные назначения кнопок, исключения из автосписка и закрепления сохраняются
по ID устройства средствами Stream Deck.

## Особенности Windows

- Приложение появляется после создания аудиосессии (обычно после воспроизведения звука).
- Привязка по полному пути EXE, не PID; все сессии одного EXE объединяются.
- Сессии защищённых/повышенных процессов могут быть недоступны; администратор не запрашивается.
- Per-app routing использует недокументированный Windows API — см. «Технический долг».
- Обновления уровней запрашиваются каждые 200 мс; поиск сессий и устройств — в фоне (пауза 2 с).

## Проверки

```powershell
npm test
pwsh -File scripts/check-profile.ps1
node scripts/smoke.mjs
node scripts/latency.mjs
node scripts/check-launch.mjs
node scripts/check-routing.mjs
./dist/local.tux.appmixer.sdPlugin/bin/native/AudioBridge.exe --self-test
```

Smoke-тест запускает собранный плагин с имитацией Stream Deck и настоящим читающим
аудиомостом. Self-test создаёт **собственную беззвучную** аудиосессию и проверяет
volume/mute/unmute только в ней; пользовательские приложения и master volume не меняются.

`npm run preview` — интерактивная демонстрация с фиктивными данными на `http://127.0.0.1:18081`.

## Технический долг

1. **Обязательная миграция на `@elgato/streamdeck` v2+.** Сейчас WebSocket-протокол
   Stream Deck реализован вручную через пакет `ws` (`src/plugin.mjs`). Это жёсткое
   требование Elgato для DRM и публикации в Marketplace: Node.js-плагины должны
   использовать официальный SDK. Вместе с ним поднять `SDKVersion` до **3** и
   `Software.MinimumVersion` до **6.9+** (сейчас 2 / 6.6).
2. **UUID с префиксом `local.`** (`local.tux.appmixer`). Перед публикацией в магазин
   переехать на вендорное пространство (например, `com.tux.appmixer`). Смена UUID —
   новая идентичность плагина: пользователям придётся переустановить его и переимпортировать
   профиль. Решить до первой отправки в Maker Console.
3. **Дублирование кода** с репозиторием `streamdeck-yamusic` (`bridge.mjs`, helpers
   рендеринга, протокол моста). Рассмотреть общую библиотеку (git submodule / npm-пакет),
   когда оба плагина стабилизируются.
4. **DRM-требования к файлам**: распространяемые файлы должны быть неизменяемы в рантайме,
   манифест не должен читаться в рантайме. Перед сабмитом проверить, что плагин ничего
   не пишет в собственную папку и не открывает `manifest.json`.
5. **Per-app routing** (`set-app-output`) опирается на недокументированный Windows API.
   Совместимость со всеми будущими сборками Windows не гарантируется; поведение при
   ошибке — откат предыдущих назначений и явное сообщение.
6. **Нет CI.** Тесты, smoke и self-test запускаются вручную на рабочей машине; добавить
   GitHub Actions (минимум `npm test` на каждый push).
7. **Локализация**: UI и тексты действий только на русском. Для магазина нужна
   английская версия (SDK i18n) или как минимум англоязычные названия/tooltip'ы.
8. **Иконки генерируются программно** (`scripts/build-icons.ps1`). Для витрины магазина
   нужен нормальный artwork (144×144 и 288×288) и галерея скриншотов.
9. **`LaunchProbe`** — dev-инструмент; не закреплён версией и не покрывается тестами пакета.
